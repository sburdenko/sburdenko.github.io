CH.01 // OPPOSITE POINTERS

Find two numbers that add up to a target

The array is sorted from smallest to largest. L starts on the left, R on the right. A pointer is simply an index: the position of an element.

Sum too small → move L
With [1, 2, 4, 7, 11, 15] and target 15, first 1 + 15 = 16, so discard 15. Now 1 + 11 = 12. Every other remaining partner for 1 is at most 11. None can reach 15. Discard 1.
Sum too large → move R
If even the smallest remaining number makes the right-hand number too large, every larger partner does too. That right-hand number cannot be in the answer.
Equal → you found the pair
Return the two indices. Stop when L meets R: the task requires two distinct elements, so a number cannot pair with itself.
L · left pointerR · right pointer

Why this is O(n)

Every failed comparison removes one position from consideration. The pointers never move back, so there are at most n − 1 pair checks. Trying all pairs takes n(n − 1)/2 checks in the worst case. Two indices use O(1) extra memory.

The condition that makes it work

The pair-sum rule needs sorted data. On [3, 2, 4], target 6, it can miss 2 + 4. Sorting first costs O(n log n) and changes the original indices. If original indices matter on unsorted data, consider a hash map.

C# · sorted pair sum

(int, int) FindPair(int[] a, int target)
{
    int left = 0, right = a.Length - 1;
    while (left < right)
    {
        long sum = (long)a[left] + a[right];
        if (sum == target) return (left, right);
        if (sum < target) left++;
        else right--;
    }
    return (-1, -1);
}

Opposite pointers also check palindromes: compare the first and last characters, then move both inward. That rule uses symmetry, so it does not need sorted characters.

CH.02 // FAST & SLOW POINTERS / FLOYD

Does this path ever end?

A linked list is a chain of nodes. Each node holds a link called next. Follow next to walk the chain. A last link pointing back to an earlier node creates a cycle: you can keep walking forever.

Phase 1 · one step, two steps
Slow follows one link per turn. Fast follows two. If fast reaches null, the chain ends. If they meet at the same node after moving, the chain loops.
Why a meeting is inevitable
Picture runners on a circular track. Once both are inside the loop, fast gains exactly one node per turn. In a cycle of length c, it closes any gap in at most c turns.
Phase 2 · find the entrance
A meeting proves a loop, but may happen deep inside it. Reset slow to the head. Now move both one link per turn. Their next meeting is the entrance.
S · slow pointerF · fast pointer
SPEED 2/s

PSEUDOCODE · CURRENT LINE HIGHLIGHTED

The yellow arrow closes the loop: TAIL.next points back to the entrance. The shaded ring is the cycle; HEAD is where the walk starts. Pink S and cyan F badges show the current nodes. Moving paths show one pink link and two cyan links in phase 1; one each in phase 2.

Why the reset finds the entrance

Let the head-to-entrance distance be μ and the cycle length be c. At the meeting, slow has taken t steps and fast 2t. Their difference t must be a multiple of c. After μ more steps, the pointer at the head reaches the entrance; the pointer at the meeting has travelled t + μ in total, which lands at that same entrance. Both move one step in this phase.

Fast & slow can also find the middle

On a list without a cycle, start both at the head and move 1 versus 2 until fast reaches the end. Slow is halfway along. With the usual loop condition, an even-length list returns the second of its two middle nodes.

Cost: O(n) time for n distinct reachable nodes, O(1) extra memory. The snapshots on this page use extra memory for rewinding; the algorithm itself does not.

C# · detect the cycle and return its entrance

// ListNode is a reference type with a ListNode next field.
ListNode FindCycleEntry(ListNode head)
{
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null)
    {
        slow = slow.next;
        fast = fast.next.next;
        if (ReferenceEquals(slow, fast))
        {
            slow = head;
            while (!ReferenceEquals(slow, fast))
            {
                slow = slow.next;
                fast = fast.next;
            }
            return slow;
        }
    }
    return null;
}

CH.03 // LEETCODE 287 · FIND THE DUPLICATE NUMBER

An array can hide a linked list

Given n + 1 integers, each in [1, n], find the one repeated value. It can appear more than twice. Do not change the array; use O(1) extra space. These constraints are what make Floyd fit.

1

Index = node

In [1, 3, 4, 2, 2], index 0 stores 1. Read that as a link: 0 → 1. Then index 1 stores 3: 1 → 3.

2

Value = next index

Following from 0 gives 0 → 1 → 3 → 2 → 4 → 2 → 4… The same array entry plays the role of a next link. Nothing is sorted or modified.

3

Entrance = duplicate value

Indices 3 and 4 both contain 2: both arrows lead to index 2. One arrives from the tail, one from the cycle. That repeated destination is the duplicate number.

PSEUDOCODE · CURRENT LINE HIGHLIGHTED

Two views, one algorithm: above, the array shows index and stored value; below, each graph node is an index and each arrow follows its value. S and F appear in both views. At the answer, the repeated array values are outlined in yellow. Follow the colored arrows to see each lookup.

Why a cycle is guaranteed here

Every value is a valid index, so no link reaches null. There are finitely many indices, so a walk must revisit one. Index 0 cannot be pointed to because values start at 1. The walk therefore has a tail before entering the cycle. At the entrance, the tail and the cycle supply two distinct incoming links: two array entries contain the same value. Since only one value repeats, this must be the answer.

C# · the same algorithm, with array lookups

int FindDuplicate(int[] nums)
{
    int slow = 0, fast = 0;
    do
    {
        slow = nums[slow];
        fast = nums[nums[fast]];
    } while (slow != fast);

    slow = 0;
    while (slow != fast)
    {
        slow = nums[slow];
        fast = nums[fast];
    }
    return slow;
}

O(n) time, O(1) extra space. No null checks are needed for this array under the problem constraints. A general array with arbitrary values does not satisfy this model. Practise LeetCode 287 ↗

!

Do not move at random

Explain why the discarded candidates cannot contain an answer. Two variables alone do not make an algorithm correct.

!

Compare nodes, not values

Two different nodes may both store 7. Floyd needs the very same node object, not equal numbers.

!

Check before two hops

Fast and fast.next must exist before reading fast.next.next. This is how the no-cycle case safely stops.

CH.05 // CHECK YOUR UNDERSTANDING

Say it before you reveal it

Q01Why move only L when the sum is too small?

R already gives L its largest remaining partner. If that sum is too small, every other partner for this L also fails.

Q02Does pair sum work with negative numbers?

Yes, if the array is sorted. The argument depends on ordering, not on values being positive.

Q03Why is the initial slow == fast not a cycle?

Both were deliberately placed at the head. Compare them only after moving.

Q04Is the first meeting the cycle entrance?

Not necessarily. In the default example the first meeting is node 6, but the entrance is node 2. Rewind and watch phase 2.

Q05Why not keep a set of visited nodes?

That works too: the first repeated node is the entrance. It uses O(n) memory; Floyd uses O(1).

Q06What should I practise next?

Try Two Sum II, Valid Palindrome, Linked List Cycle, Linked List Cycle II and Middle of the Linked List. Write the movement rule before the code.
