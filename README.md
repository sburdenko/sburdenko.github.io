# Bathys

**Bathys** (от греческого βαθύς — «глубокий») — платформа интерактивных курсов: короткие уроки
по пять минут, где на каждом экране что-то делаешь сам, а под капотом разбирается, как всё
устроено внутри. Чистый HTML, CSS и ES-модули, без сборки и зависимостей.

Сайт: https://sburdenko.github.io — главная страница открывает курсы. Длинные интерактивные
конспекты («кассеты») живут отдельным модулем — [полкой](./shelf/).

**Языки.** Русский и английский. Язык выбирается в профиле (`#/profile`) и общий с полкой
кассет: выбор хранится в localStorage (ключ `tape-lang`), язык можно задать и ссылкой — `?lang=en`.
Без выбора включается английский.

**Вход.** Вход через Google сделан через абстракцию провайдера (`learn/auth/`): приложение
видит только интерфейс `auth` (`user`, `onChange`, `signIn`, `signOut`), а Firebase — один из
адаптеров; сейчас подключён проект Firebase `bathys-d6656` (`learn/auth/config.js`). Курсы работают
и без входа, прогресс пока хранится в браузере. Настройка — в разделе «Вход через Google».

## Курсы

Курсы — основной формат Bathys: короткие уроки по пять минут в духе Duolingo и Busuu. На каждом экране что-то делаешь сам: выбираешь ответ, расставляешь шаги,
собираешь код из плиток, соединяешь пары, гоняешь стенды. Ошибка возвращает карточку в конец
урока, за уроки начисляются XP и звёзды, считается серия дней; прогресс хранится в браузере.
Уроки рассчитаны на новичков, а опытным предназначены раскрывающиеся блоки «Глубже».
Каждый урок есть на русском и на английском: `<урок>.js` и `<урок>.en.js` рядом, у курса —
`course.js` и `course.en.js`. Тест `tests/learn-en.test.js` сверяет их: та же структура,
те же ответы и решения стендов, ни одной кириллической буквы в английской версии.

Курсы сгруппированы на главной: «.NET и C#», «3D и графика» и «Ещё» (то, что скоро появится).

## Курсы как данные

Все курсы хранятся не в модулях, а в данных (`content/<курс>/`) — так же их читают другие языки
и будущий мобильный клиент. Урок состоит из структуры и строк:

```
content/memory/course.json                 разделы и список уроков (на месте текста — метка ⟦⟧)
content/memory/lessons/mem.u1.l1.json      структура: типы карточек, верные ответы, решения стендов, код
content/memory/i18n/ru/mem.u1.l1.json      строки: { "cards/3/q": "…" }, путь внутри структуры
content/memory/i18n/en/mem.u1.l1.json
content/memory/bundle.ru.json              весь курс на одном языке одним файлом (его грузит сайт)
```

Тексты стендов тоже данные: код моделей и стендов зовёт `tl('ключ', { переменные })` (строка на текущем
языке), `bi('ключ')` (строка на всех языках — для подписей объектов) и `tp('ключ', n)` (число со словом:
формы через «|», «точка|точки|точек»). Значения подставляются в `{имя}`. Тест следит, чтобы ключи в коде
и в `content/rigs/` совпадали, а подстановки в ru и en были одинаковыми.

Загрузчик (`learn/content.js`) в браузере берёт `bundle.<язык>.json`, а при отсутствии языка —
английский, потом русский; в тестах и инструментах читает исходные файлы. Новый язык — это новая
папка `i18n/<язык>/`, без правок структуры. `bundle` собирается из исходников командой
`npm run stamp` (её и надо запускать перед коммитом); тест падает, если он устарел.

Тесты: `tests/content.test.js` — у каждой строки есть ru и en, пути существуют, меток не осталось,
bundle свежий; `tests/learn.test.js` и `tests/learn-en.test.js` проходят каждый урок как раньше.
Новый урок пишут как два модуля (ru и en) и добавляют командой
`node tools/content-add.mjs <курс> урок.js урок.en.js`, затем вписывают id в `course.json`.
Курс из старых модулей переводит `node tools/content-convert.mjs <папка курса>`.

## Стенд algo: задачи кассеты «Паттерны алгоритмов» в уроке

`learn/models-algo.js` (модель без DOM) и `learn/rigs-algo.js` (отрисовка) показывают в уроке любую из 72 задач
кассеты 06: трасса, SVG и тексты шагов берутся из `algorithms/patterns/` без копирования, стили SVG —
правила `.stage …` из её `style.css`, подключённые с приставкой `.algo-rig`.

```js
{ t: 'rig', rig: 'algo', problem: 'coin',             // id задачи — id стенда кассеты, см. ALGO_IDS
  input: { coins: [1, 2, 5], amount: 11 },            // необязательно: поверх примера кассеты, те же проверки полей
  task: 'Предскажи dp[6] до того, как стенд его посчитает.',
  goal: { step: 'end',                                // или { step: 5 }, или { event: 'dp.ev.done' } — куда дойти
          ask: { at: 6, options: ['1', '2', '3'], answer: 1, q: '…', explain: '…' } },
  solve: ['end', 'pick:1', 'end'] }
```

- Кнопки ⏮ ◀ ▶ ⏭ — действия `reset`, `prev`, `next`, `end`; счётчик «Шаг i из n»; под картинкой — текст шага
  и переменные кассеты на текущем языке.
- «Предскажи» (`goal.ask`, синоним `goal.predict`): `at` — событие, которое надо предсказать (номер или ключ;
  ключ — первое такое событие). Стенд встаёт на шаг перед ним, ▶ и ⏭ заблокированы до верного ответа
  (`pick:N`); неверный вариант зачёркивается. Варианты (2–4) — строки, `{ ru, en }` или
  `{ event: '<ключ>', label }`; если все варианты с `event`, `answer` можно не писать — он берётся из трассы,
  а если написан, модель сверяет его с трассой.
- Цель выполнена, когда стенд дошёл до шага цели (по умолчанию — до конца, при одном вопросе без `step` —
  до предсказанного события) и вопрос, если есть, решён. Ошибки в карточке (нет задачи, ввод вне правил,
  `at` вне трассы) бросают исключение с понятным текстом — тесты ловят их сразу.
- Задачи: hash — twoSum, dup, anagram, longestConsec, psum, firstMissing; twoptr — moveZeroes, container,
  threeSum, trap; window — maxAvg, longest, minLen, charReplace, minWindow; binary — bsearch, rotated, koko,
  median; stack — parens, daily, minStack, histogram; list — cycle, removeNth, reverse, lru, reverseK;
  graph — flood, islands, oranges, course, ladder; tree — maxDepth, levelOrder, validBst, lca, maxPath;
  heap — kth, stones, topK, mergeK, medianStream; back — subsets, perms, combSum, wordSearch, queens;
  greedy — jump, stock, intervals, mergeIv, candy; dp — climb, coin, lcs, lis, edit, regex.
  Названия и номера LeetCode — в `ALGO[id].title / num`; новая задача кассеты попадает в реестр сама.

## Вход через Google

Firebase Authentication работает со статическим сайтом: вход идёт прямо из браузера,
сервер не нужен.

1. [console.firebase.google.com](https://console.firebase.google.com) → Add project.
2. Project settings → Your apps → Web (`</>`) → зарегистрировать приложение; хостинг не нужен.
3. Скопировать объект `firebaseConfig` в `learn/auth/config.js` (поле `firebase`). Эти значения
   не секретные — их видит любой браузер.
4. Authentication → Sign-in method → Google → Enable.
5. Authentication → Settings → Authorized domains → добавить `sburdenko.github.io`
   (`localhost` там уже есть).

Другой провайдер — новый модуль в `learn/auth/` с `createAdapter(settings, emit)` и строка
в `ADAPTERS` в `auth.js`; остальное приложение менять не нужно.

## Режим разработчика

В профиле (`#/profile`) или ссылкой `?dev=1` включается режим разработчика: в шапке урока
появляется кнопка ⏭ — она засчитывает карточку верной и переходит к следующей, чтобы быстро
прощёлкивать урок при проверке. Очки и звёзды при этом не настоящие. Кнопка ↺ рядом (есть
всегда) сбрасывает текущую карточку или стенд в начальное состояние. `?dev=0` выключает.

## Жалобы на карточки

На каждой карточке урока справа вверху кнопка ⚑. Она открывает окно: категории проблемы
(неверный ответ, непонятно, опечатка, неточный факт, перевод, стенд, вёрстка, сложность,
идея, другое) и поле для своего текста. Отчёт уходит в коллекцию `reports` Cloud Firestore:
курс, урок, номер карточки, начало вопроса, язык, категории, текст, id пользователя (если
он вошёл) и версия сборки. Если сеть недоступна, отчёт ждёт в localStorage и уходит при
следующем запуске. Логика отчёта — `learn/reports/report.js`, отправка — через адаптер
(`reports.js` → `firestore.js`), как и вход.

Чтобы отчёты принимались, опубликуй правила из `firestore.rules`: Firebase console →
Build → Firestore Database → Create database (режим production) → Rules → вставить → Publish.
Правила разрешают только создавать отчёты нужной формы; читать, менять и удалять через сайт
нельзя. Читать отчёты: `node tools/reports.mjs` (нужен сервисный аккаунт с ролью
Cloud Datastore Viewer и `gcloud auth activate-service-account`) или в консоли Firebase.

## Запуск и проверка

```sh
python3 -m http.server 8000   # или любой статический сервер
npm test                      # node --test tests/*.test.js
npm run typecheck             # проверка типов в js (JSDoc + checkJs), нужен npm install
npm run stamp                 # перед коммитом: обновить метки ?v= у js и css
```

`npm run stamp` проставляет всем внутренним ссылкам на модули и стили одну общую
метку `?v=<дата>`. GitHub Pages отдаёт файлы с `max-age=600`, и без метки браузер
может смешать свежий HTML со старым модулем — тогда граф импортов не собирается и
страница молча остаётся пустой. Общая метка меняет все адреса разом, так что смешать
версии невозможно. На случай любой другой поломки в каждой странице сидит сторож:
если скрипты не загрузились, сверху появляется красная плашка с причиной.

Файлы подключаются как ES-модули, поэтому открывать `index.html` по `file://` не получится —
нужен локальный сервер. Сборка не требуется: что лежит в репозитории, то и раздаёт GitHub Pages.

## Типы

Код остаётся обычным JavaScript без сборки, но типы проверяются: `npm install`, затем
`npm run typecheck` (TypeScript с `checkJs`, конфиг — `tsconfig.json`). Форма данных описана в
`learn/types.d.ts` (карточки, урок, раздел, курс), а ядро подписано в JSDoc:
`/** @param {...} */` перед функцией. Проверяются `learn/`, `tools/` и тесты платформы; старые кассеты
в проверку не входят. Тест `tests/content.test.js` проверяет те же формы на данных курсов. Адреса вида
`./x.js?v=…` tsc не понимает, поэтому `tools/typecheck.mjs` прогоняет копию исходников с метками снятыми.

## Про модели

Это учебные визуализации, а не бенчмарки. Миллисекунды и байты на кассете про батчинг — условные
коэффициенты, которые позволяют сравнивать техники между собой; реальные ответы дают Unity Profiler
и Frame Debugger. Алгоритмы BFS и DFS, наоборот, настоящие: страница показывает ровно те события,
которые порождает код в `traversal.js`.
