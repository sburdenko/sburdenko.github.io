## 3. Общие механики стенда (чем он отличается от кассет 01–06)

### 3.1 Пошаговый исполнитель кода («Line-stepper»)

Главная новая механика. Каждый стенд показывает **настоящий фрагмент Python** и рядом —
картинку состояния. При перемотке:

- в коде подсвечивается строка, которая выполняется сейчас (`.ln.cur`), и слабее — та,
  что была предыдущей;
- справа/снизу обновляется «память»: таблица переменных (имя → стрелка → объект),
  и объекты рисуются как коробки с типом и значением;
- внизу растёт «консоль»: всё, что `print` уже напечатал к этому шагу;
- подпись шага объясняет, что произошло, в одну-две фразы (ключ i18n + аргументы).

Реализация: модель стенда — JS-функция `trace(params) → { events, result }`, где
каждое событие `{ line, key, args, mem, out, mark }`:

| Поле | Что |
|------|-----|
| `line` | 1-based номер строки фрагмента, которая выполняется |
| `key`, `args` | ключ подписи и аргументы для `t()` |
| `mem` | снимок памяти: `{ frames: [{ name, vars: {x: objId} }], objects: {objId: {type, value|items}} }` — неизменяемые копии, не ссылки |
| `out` | массив строк, напечатанных к этому моменту |
| `mark` | что подсветить на картинке (индексы, ячейки, стрелки) — произвольно для вида |

Фрагмент Python хранится рядом с трассой как строка; трасса пишется вручную на JS и
**обязана воспроизводить семантику Python ровно для этого фрагмента**. Это не интерпретатор:
мы не исполняем Python в браузере ради перемотки, мы заранее знаем, что делает конкретный
код. Такой подход уже работает на кассетах 02 и 06.

Гарантия честности (см. §8): тест запускает каждый фрагмент настоящим `python3` и сверяет
его stdout с `out` последнего события трассы на тех же входных данных.

### 3.2 Два режима картинки

- **Память** (по умолчанию для PY-01…PY-05): имена → стрелки → объекты. Объект —
  коробка со скруглёнными углами, тип в шапке, значение внутри; список — ряд ячеек с
  индексами сверху (0, 1, 2…) и снизу (−1, −2…); словарь — таблица ключ → значение;
  изменяемые объекты обведены пунктиром, неизменяемые — сплошной линией.
- **Структура** (для PY-03 и PY-06): массив столбиков для сортировок, сетка для матриц
  и лабиринтов, дерево, стек/очередь, граф — переиспользуем `view-kit.js` кассеты 06 через
  `python/shared/`.

### 3.3 Редактируемый ввод

Как на кассете 06: у каждого стенда поля ввода с проверкой (`inputs.js` переиспользуется),
кнопки «🎲 Случайно» и «↺ Пример». Для фрагментов с `input()` поле ввода играет роль
того, что «напечатал пользователь».

### 3.4 «Попробуй сам»: живая консоль Python

У каждого стенда есть кнопка `▶ RUN` под редактируемой копией фрагмента. Она запускает
**настоящий Python в браузере** через Pyodide (WebAssembly-сборка CPython).

Это единственное отступление от правила «без зависимостей»: Pyodide загружается лениво
с CDN (`cdn.jsdelivr.net/pyodide/v0.27.x/full/`) только после первого нажатия `▶ RUN`
на странице; до этого страница работает полностью, как и остальные кассеты. Если сети нет,
кнопка показывает понятное сообщение и предлагает установить Python локально (ссылка на
python.org и инструкция в три строки). Размер ядра Pyodide — порядка 10 МБ, загрузка
один раз на сессию, кэшируется браузером.

Детали консоли:

- однофайловый редактор на `<textarea>` с подсветкой через оверлей (без CodeMirror);
  Tab вставляет четыре пробела, Shift+Enter запускает;
- `input()` перехватывается и показывает модальное поле, как в школьном IDLE;
- вывод, исключения с трейсбеком и время выполнения — в панели «консоль»;
- лимит времени 5 с (воркер убивается и перезапускается), чтобы `while True:` не вешал
  страницу;
- кнопка «↺ как в учебнике» возвращает исходный фрагмент;
- на мобильном консоль остаётся, но становится ниже.

Pyodide живёт в Web Worker (`python/shared/py-worker.js`), общение — через `postMessage`.

### 3.5 Задания «угадай вывод» и мини-квизы

После группы стендов — карточка: показан код, три-четыре варианта «что напечатает»,
после ответа — пояснение и кнопка «посмотреть по шагам», которая открывает тот же код
в line-stepper. Это основной способ проверить, что Варвара поняла, а не просто смотрела.

Форматы карточек:

- **Вывод** — выбрать, что напечатает `print`;
- **Ошибка или нет** — упадёт ли код и с каким исключением;
- **Допиши строку** — одно поле ввода, сверяется с ожидаемыми вариантами (нормализуем
  пробелы);
- **Поставь по порядку** — перетащить строки кода в правильный порядок (для сортировок
  и рекурсии).

### 3.6 Блок «⚙ Под капотом»

`<details>`-блок в каждой главе. Содержит: как это устроено в CPython, что покажет
`dis`/`sys.getsizeof`/`id`, сложность операций, ловушки, и сравнение с C# в две колонки
(`List<T>` против `list`, `Dictionary` против `dict`, `struct` против «всё объект»,
`IEnumerable` против протокола итератора, `using` против `with`, `async/await` там и там).

### 3.7 Шпаргалка

У каждой кассеты в конце — глава «Шпаргалка»: плотная таблица синтаксиса и методов из
этой кассеты с одной строкой примера на каждый пункт. Печатается через `@media print`
нормально (без шумов и сканлайнов).

### 5.4 Контракт трассы

```js
// model-flow.js
export function factorialTrace(n) {
  const mem = heap();                       // из shared/mem.js
  const events = [];
  const step = (line, key, args = [], mark = null) =>
    events.push({ line, key, args, mark, mem: mem.snapshot(), out: out.slice() });
  …
  return { events, result };

```

Правила:

- модели не импортируют DOM и `t()`; возвращают ключи;

- у трассы есть `out` — массив строк, который должен совпасть с реальным stdout.

## 6. UI и визуальный язык стенда

## 8. Тесты

`tests/python-*.test.js`, запускаются общим `npm test`:

1. **Трассы против Python.** Для каждого фрагмента `snippets-*.js` с параметрами примера
   и для 20 случайных входов тест пишет фрагмент во временный файл, запускает `python3`
   (если его нет в системе — тест пропускается с предупреждением, не падает) и сверяет
   stdout с `out` последнего события. Это главная гарантия, что картинка не врёт.
2. **Номера строк.** Каждый `event.line` лежит в `[1, число строк фрагмента]`, и ни одна
   строка с кодом (не пустая, не комментарий) не остаётся непосещённой, если трасса дошла
   до конца на примере.
3. **Снимки памяти.** Снимки неизменяемы (`Object.isFrozen`), ссылки в `vars` указывают на
   существующие объекты, объекты не дублируются между шагами без изменений.
4. **Алгоритмы PY-06.** Результаты сортировок/поисков/подсчётов сверяются с brute force
   на случайных данных, как на кассете 06; счётчики сравнений для пузырька равны
   `n(n−1)/2` при худшем входе и так далее.
5. **Квизы.** У каждой карточки ровно один правильный ответ, пояснение непустое, ссылка
   «по шагам» указывает на существующий стенд.
6. **i18n.** Все ключи присутствуют в обоих языках, ни один `data-i18n` в HTML не повис
   (переиспользуем `tests/i18n.test.js`).
7. **Подсветка Python.** Токенизатор не теряет символы (конкатенация токенов равна
   исходнику) на всех фрагментах стенда.
8. **Pyodide-загрузчик.** Без DOM и сети: очередь запусков, таймаут, перехват `input()`
   — тестируется с фейковым воркером.

Покрытие чистых моделей — не ниже 80 %, как и везде.
